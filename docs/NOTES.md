*Test Card — browser app turning a show's output map (Resolume/Pixel Peeker/Blend Calc) into per-output test pattern PNGs; the SMPTE RP 219 pattern is measured from ffmpeg, not transcribed*

**PUBLIC since 2026-08-05** — the private-repo statements below are historical; the repo, its Docker packaging and its `/software` page are all live. See [browser tools published](https://github.com/stoatworks-labs/fleet-notes/blob/main/notes/project_browser_tools_published.md).

**Test Card** — test patterns for every physical output in a show. React/TS/Vite
static SPA, no backend. `~/Projects/test-card`, MIT, **GitHub PRIVATE** at
`stoatworks-labs/test-card` (created 2026-08-01, branch `main`). **LIVE at
test-card.stoatworks-labs.com** — static-assets Worker, custom domain attached in
`wrangler.toml` as a `**routes**` entry with `custom_domain = true` rather than by
hand in the dashboard, so a fresh deploy cannot come up without the hostname. On
the website (projects.json + `/thumbs/test-card.png`).

Imports a **Resolume advanced output XML**, a **Pixel Peeker interchange JSON**
or a **Blend Calc design JSON**; renders SMPTE RP 219, 75% bars, user grids,
alignment patterns, LED tile maps, solid fields, greyscale and pixel-check as one
PNG per output (ZIP + manifest when several), or as a single **composition
canvas** — play that through Resolume and each output shows its own name, which
is the fastest proof the output map is what you think it is.

**The RP 219 pattern was measured, not transcribed** — free descriptions of the
standard disagree with each other and mostly omit the code values.
`scripts/extract-rp219-reference.py` renders ffmpeg's `smptehdbars` at 4 sizes
(incl. non-16:9 DCI) and run-length analyses it; result committed as JSON so
tests need no ffmpeg. See [ffmpeg test pattern traps](https://github.com/stoatworks-labs/fleet-notes/blob/main/notes/reference_ffmpeg_test_pattern_traps.md) for the two
traps that produce plausible-but-wrong output. Model: rows 7/12, 1/12, 1/12,
3/12; columns a=W/8, b=3W/28, closing exactly as 2a+7b=1.

**Colours are computed from R'G'B' through Rec.709, never tabulated** — all 15
land exactly on the measured values, which is itself the proof the measurement
is sound. Only +I and +Q are constants (I/Q-axis signals, not colours, not
derivable).

Deliberate deviation: ffmpeg ceils each bar and dumps the remainder in the last
column, so its right grey block is up to **6px narrower** than its left. This
rounds cumulative boundaries to nearest instead, keeping the pattern symmetric —
an asymmetric test pattern is a defect. Test allows 8px column drift, exact rows.

**Neither sibling's parts library is vendored** ([pixel peeker](https://github.com/stoatworks-labs/pixel-peeker/blob/main/docs/NOTES.md) (`pixel-peeker`),
[blend calc](https://github.com/stoatworks-labs/blend-calc/blob/main/docs/NOTES.md) (`blend-calc`)): a Pixel Peeker *project* file is refused (cabinets are
library refs in mm — use Export→JSON), and Blend Calc's missing projector raster
is asked for. Critical: **Blend Calc never persists its solved overlap** — in
`fit-width` the vertical overlap is computed, shown as "(solved)", and not
written back, so the JSON's value is a stale input. The importer flags the axis.

Every `Output` carries `rasterSource`; **`slice-bounds` means guessed** and stays
badged in UI, warnings and the ZIP manifest — a Resolume screen on a real display
or capture card records an `idHash` but no dimensions.

88 tests, all offline. Importers tested against **real files only** — Arena
7.27.0's own AdvancedOutput.xml + a saved preset, plus exports generated by
running blend-calc's (`BLEND_CALC_XML_OUT`) and pixel-peeker's
(`PP_WRITE_ARTEFACTS`) own suites.

Deliberately no `diag` module (static page, same call as blend-calc); no ZIP64;
store-only ZIP (PNGs are already DEFLATEd) hand-rolled with CRC-32 against the
published vector. Canvas limits are checked before drawing because **browsers
return a blank image over the limit rather than an error** — an 8K wall would
otherwise export a folder of empty PNGs discovered on site.
